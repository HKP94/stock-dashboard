### 1-2. ★같은 두 색이 '등락'과 '상태'를 겸한다

| 문맥 | `C.ok`/`C.bad` 사용 줄 수 |

## 3. ★Phase 1 등락색 전환 계획 (부분 적용 금지)

현행이 관례와 반대이므로 **일괄 전환**한다. 화면마다 색 의미가 다르면 오독 사고다.

**전환은 단순 치환이 아니다** — `C.ok`/`C.bad` 200회 사용처를 **두 축 중 하나로 분류**하는 작업이다.

1. **분류**: 각 사용처를 `등락`(가격·손익·등락률·상승여력) vs `상태`(심리·신호·강세약세·점수 색)로 판정. 실측 시작점 = 등락 19줄 / 상태 12줄(나머지는 파생·간접 참조).
2. **치환**: 등락 → `--price-up`/`--price-down`(**의미 반전**: 기존 `C.ok`→`--price-up`, `C.bad`→`--price-down`) / 상태 → `--state-positive`/`--state-negative`(**의미 유지**).
3. **화살표·기호 동시 점검**: `▲`/`▼`는 방향 기호라 그대로지만, 색과 함께 봐야 오독이 안 난다.
4. **한 PR에 전부**. 탭별 분할 금지.
5. **검증**: 전 탭 스크린샷 대조 + `C.ok`/`C.bad` 잔존 0 확인.

**되돌릴 여지**: 라이트 테마 토큰도 한국 관례로 정의돼 있어, 테마를 바꿔도 등락 의미는 일관된다.

## 4. M-able 참조 근거와 한계

- **참조한 것**: 다크 기준 배경 3단 구조, 큰 숫자 중심의 정보 위계, 한국 증권앱의 **등락색 관례(상승 빨강/하락 파랑)**, 촘촘한 카드 밀도.
- **참조하지 않은 것 / 금지**: **브랜드 자산 복제 금지** — 로고·아이콘·고유 색상값·폰트·일러스트·문구를 그대로 가져오지 않는다. 위 토큰 색상값은 전부 ATLAS가 자체 선정한 값이며 M-able 팔레트를 추출·복제한 것이 아니다.
- **판단 기준**: 채택하는 것은 **관례와 정보 구조**(사용자가 이미 학습한 것)이지 **표현물**이 아니다.

## 6. Phase 1 이후를 위한 메모 (지금 손대지 않음)

- `App.css`는 Vite 스캐폴드 잔재이며 **import되지 않는다** → Phase 1에서 삭제 대상.
- `index.css`의 하드코딩 11개소(스크롤바·포커스링·`.chip-hover`)는 토큰으로 치환 가능.
- `ui.jsx`의 `C` 객체는 Phase 1에서 **토큰 참조 래퍼**로 바꾸면 200회 사용처를 파일별로 흩지 않고 한 곳에서 전환할 수 있다(`C.ok` → `var(--state-positive)`). 다만 등락/상태 분류는 사용처별로 봐야 하므로 래퍼만으로는 끝나지 않는다.
