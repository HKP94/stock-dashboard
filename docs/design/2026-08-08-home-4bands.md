## 2. PM 수정 4건

### ① 당일 수급 = export 1줄 추가 (백엔드 0변경 원칙보다 목적 우선)

`investor_flow`는 3일 합계·신호만 내보내고 있었다. **"외국인 순매수일"은 당일 판정이 본질**이라
3일 합계로는 규칙이 성립하지 않는다. 쿼리는 이미 `foreign_net`을 select 중이었으므로
`_format_investor_flow`에 두 줄만 추가했다(수집·계산 무변경).

```
+ "foreignNet1d":     _f(row.get("foreign_net")),
+ "institutionNet1d": _f(row.get("institution_net")),
```

카드는 **당일(방향 화살표) + 3일(추세)** 를 병기한다. 3일 +인데 당일 −인 경우가 실제로 있고,
그때 3일만 보면 '순매수'로 오판한다 — 회귀 가드가 이 케이스를 고정한다.

> **"3일 수급"으로 정직하게 라벨링** 하는 타협안은 PM이 기각했다. 라벨이 정직해도
> 규칙 판정이 안 되는 보드는 목적 미달이기 때문이다.

### ② `broken` 종목은 손절선을 지어내지 않는다

`momoZone.state === 'broken'`이면 `stop`/`target`이 **없고** `reclaim`만 있다(#90 철학 —
재탈환 전엔 매수·손절선을 제시하지 않는다). `stopDistance()`가 `kind: 'reclaim'`으로 구분해
돌려주고, 카드는 「재탈환 필요 ₩247,950 · 재탈환 전 손절선 없음」으로 표기한다.
**없는 손절선을 0이나 null 숫자로 채우지 않는다.**

### ③ 트리거: 보유 종목 외국인 당일 순매수 양(+) 전환

①의 당일값을 쓰되 **종목 하드코딩 없이 보유 전체에 일반화**했다(삼성 규칙은 자연히 커버된다).
§2 준수 — 조건 충족은 **사실 표시**이며 매매 지시가 아니다(밴드 헤더에 명시).

### ④ 라이트 테마 기본 전환

`main.jsx`가 `data-theme`를 `localStorage.getItem('atlas-theme') || 'light'`로 설정하고,
헤더에 토글(`◐`/`◑`)을 붙였다. 선택은 localStorage에 유지된다.

- `StyleGuide.jsx`가 `useState('dark')`로 기본값을 **하드코딩**해 앱과 다른 테마로 뜨던 것을
  문서 속성을 읽도록 고쳤다.
- **`color-scheme` 선언 추가**(`:root` dark / `[data-theme=light]` light). 이 선언이 없으면
  Chrome의 강제 다크(auto-dark-mode)가 **라이트 화면을 렌더 단계에서 통째로 반전**시킨다.
  computed 값은 라이트인데 눈에는 어둡게 보여 디버깅이 어려운 종류의 버그다.

## 3. 계산 위치 (§0 "결정론은 코드로"와의 경계)

2열의 규칙 판정은 **새로 만들지 않았다**. `buildTriggers`는 이미 판정된 값을 조합할 뿐이다:

| 트리거 | 출처 | 성격 |
|---|---|---|
| 목표가 근접·RSI 과열·데드크로스… | `rules.py` → `flagsAction` | 백엔드 판정 |
| 손절선 이탈·접근 | `price` vs `momoZone.stop` | 두 저장값의 **단순 비교** |
| 외국인 당일 순매수 | `investorFlow.foreignNet1d > 0` | 저장값의 **부호** |
| 3축 등급 축소 | `grade` | 백엔드 판정 |

프론트가 만드는 건 비교·부호·정렬뿐이고 **새 점수·새 임계·새 판정은 없다**.
복합 규칙(수급＋추세＋등급 결합)이 필요해지면 그건 `rules.py` 소관이며 별도 PR이다.

## 5. 발견해서 같이 고친 것

- `fmtEok(null)`이 `+0.0억`을 반환했다(`Number(null) === 0`). **결측과 실제 0원 수급이 구분되지
  않는다** — 명시적 null 체크 추가.
- 목표가를 이미 넘긴 종목(MSFT)의 목표 거리가 `+-7.9%`로 렌더됐다. 부호 계산을 분리하고,
  그 경우 「목표가 상회」로 문구를 바꿨다.
- `flagDesc`(플래그별 근거 문장)가 소비처를 잃어 미사용이 됐다. 삭제 대신 트리거 행의 설명으로
  되살렸다(지웠다면 "목표가 근접"만 남고 근거가 사라진다). 이를 위해 `buildTriggers`가
  원본 플래그 문자열을 `flag`로 실어 보낸다.
